# Deep link: открыть диалог по ссылке

Ссылка `razum-assistant://session/<id>` открывает в приложении «РАЗУМ Ассистент» указанный диалог (сессию Hermes). Её даёт браузерное расширение («Открыть в РАЗУМ Ассистент»).

## Формат

- Схема `razum-assistant`, хост строго `session`, затем один сегмент пути: id сессии `[A-Za-z0-9_-]{1,128}` (браузерные сессии начинаются с `brw-`).
- Пример: `razum-assistant://session/brw-3f9a1c`.
- Допускается один завершающий `/`. Любое другое (query, hash, лишние сегменты, `%`-кодировки, `..`, чужие хосты и схемы) игнорируется; в лог пишется только факт отказа, без значения.
- По ссылке выполняется единственное действие: открыть диалог. Отправки сообщений и запуска команд нет.

## Как работает

- Разбор: чистая функция `parseDeepLink` в `src/main/deep-link.ts` (белый список).
- Windows/Linux: ссылка приходит в argv при первом запуске и в событии `second-instance` (`pickDeepLinkFromArgv`). macOS: событие `open-url`.
- Main буферизует последнюю ссылку, пока рендерер не подписался. Layout монтируется только после установки и настройки и подписывается (`window.hermesAPI.onDeepLinkOpenSession`) только после восстановления выбранного профиля (не дольше 30 с ожидания) — иначе диалог открылся бы в профиле `default`. Подписка служит сигналом готовности.
- Доставка с подтверждением: main держит ссылку, пока рендерер не подтвердит, что взял её (`deep-link-ack` с номером ссылки), и пересылает её при каждом новом сигнале готовности. Ссылка, ушедшая в перезагружающуюся страницу или потерянная иначе, не пропадает. Повторно пришедшую ссылку с тем же номером preload только подтверждает, не открывая второй раз. Отписка, падение рендерера и закрытие окна приостанавливают отправку до следующей готовности.
- Если окна ещё нет (запуск по ссылке, ссылка во время скрытого старта из автозагрузки) — окно показывается, как только готово.
- Каналы IPC: `deep-link-open-session` (main → renderer, payload `{ sessionId, seq }`), `deep-link-renderer-ready`, `deep-link-renderer-gone` и `deep-link-ack` (renderer → main).
- В рендерере Layout открывает диалог через `handleResumeSession(id)` (`openSessionWithRetry` в `src/renderer/src/screens/Layout/deepLinkOpen.ts`):
  - временные сбои (связь ещё поднимается, сеть, таймаут, 5xx, 408, 429) тихо повторяются через 2, 5 и 10 с; на время ожидания видна плашка «Открываю диалог по ссылке…» с «Отмена»; если и последняя попытка не удалась — плашка «Не удалось открыть диалог» с «Повторить»;
  - окончательные ошибки показываются сразу, без повторов: 404 — «Диалог не найден», прочие 4xx — «Не удалось открыть диалог»;
  - «Повторить» на плашке сохраняет проверку «диалог существует», если её требовала исходная ссылка;
  - «Отмена» на плашке «Открываю…» отменяет только эту ссылку: если человек уже открыл другой диалог, его загрузка не прерывается; открытие другого диалога само убирает плашку «Открываю…»;
  - пустая история по ссылке считается «диалог не найден» (плашка «Диалог не найден»): иначе открылся бы пустой чат, привязанный к чужому id, и следующее сообщение ушло бы в него;
  - плашка «Не удалось открыть диалог» показывается и при неудачном открытии из списка, и при неожиданном сбое после загрузки (тихих неудач нет);
  - в режиме SSH (legacy) сбой SSH больше не превращается в пустой список, поэтому недоступный сервер не выдаётся за «диалог не найден».
- Побеждает последнее действие: если, пока грузится или ждёт повтора диалог по ссылке, человек открыл другой диалог, нажал «Новый чат», вкладку, выбрал агента или ушёл в другой раздел, загрузка по ссылке экран не перехватывает, повторы прекращаются, плашка ошибки убирается.
- Регистрация схемы:
  - Windows, установщик NSIS: макросы `build/installer.nsh` пишут `HKCU\Software\Classes\razum-assistant` при установке и удаляют при удалении (при обновлении не трогают). Сам electron-builder для Windows схему не регистрирует.
  - Windows, MSI (раскатка политикой): установщик схему не пишет — у каждого пользователя ссылка заработает после первого запуска приложения; после удаления MSI запись в реестре остаётся.
  - Все платформы: при каждом запуске `app.setAsDefaultProtocolClient`. Portable-сборка регистрирует свой настоящий exe (`PORTABLE_EXECUTABLE_FILE`), а не временную папку распаковки. В dev (`npm run dev`) регистрации нет, чтобы не перехватывать ссылки у установленного приложения; включить — `HERMES_DEV_REGISTER_PROTOCOL=1`.
  - macOS — `Info.plist`, Linux — `.desktop` (оба из `protocols` в `electron-builder.yml`).

## Как проверить

Windows (установленное через NSIS приложение; для `npm run dev` — с `HERMES_DEV_REGISTER_PROTOCOL=1` после первого запуска):

```
start razum-assistant://session/<id>
```

Ожидание: приложение запускается (или выходит на передний план) и открывает диалог `<id>`. Если приложение ещё не вошло, диалог откроется после входа. Несуществующий id — плашка «Диалог не найден». Недоступный сервер — после повторов плашка «Не удалось открыть диалог» с кнопкой «Повторить».

Важно при проверке с ПК разработчика: не запускайте приложение и установщик из процессов внутри песочниц приложений (например, из Desktop Commander в Claude Desktop, это MSIX-контейнер) — они видят виртуальные `%LOCALAPPDATA%` и `HKCU`. Запускайте из Проводника.

Проверка отказа: `start razum-assistant://session/../x` ничего не открывает, в консоли main появляется `[DEEP-LINK] Ignored unsupported link`.

Linux: `xdg-open razum-assistant://session/<id>`. macOS: `open razum-assistant://session/<id>` (работает только из установленного .app).
